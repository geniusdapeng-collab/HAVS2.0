# 暴风战斧系统 v6.7.0 改造方案 — 基于 HyperrealitySystem 25字段规范的全链路升级

## 一、改造总览

### 1.1 改造目标

将现有暴风战斧系统（18字段 → 1500字符）升级为符合 HyperrealitySystem v3.0 标准的生产系统（25字段 → 2500字符），核心变化：

| 维度 | 现有系统 | 目标系统 | 变化 |
|------|---------|---------|------|
| 字段数 | 18个 | 25个 | +7个新增字段 |
| 字符上限 | 1500 | 2500 | +67%表达空间 |
| 架构模式 | Stage串联 | Layer+Phase+Agent并行 | 并行化重构 |
| 质量检查 | RenderPipelineGuard + RenderQAChecker | FieldGuard（25项检查） | 全面升级 |
| 导演增强 | 无 | DirectorSkillInjector（3套模板） | 新增 |

### 1.2 核心设计原则

1. **向后兼容**：保留现有 Stage 体系命名，内部映射为 Agent 执行
2. **增量升级**：不改底层渲染接口（Seedance），只改上游 prompt 组装
3. **并行优先**：Phase 1/2 内各 Agent 可并行执行，缩短总耗时
4. **质量兜底**：硬编码注入 + LLM生成 + 专用Agent 三条链路互补

### 2.2 新增字段详解（7个）

#### 新增1：【导演指令】director_instruction（P0）

**业务功能**：统摄所有字段的风格锚点，防止风格碎片化。

**四要素模型**：
- 风格定位：`好莱坞大导演质感` / `纪录片真实感` / `商业广告精致感`
- 写实要求：`写实风格，无特效，无科幻元素`
- 情绪基调：`冷静专业` / `紧张刺激` / `温馨感人`
- 技术方向：`电影级画面，35mm胶片感，自然光效`

**生成方式**：双保险机制
- 主：LLM根据 `filmType` + `creativityIndex` 生成
- 兜底：硬编码模板库（剧情片/纪录片/广告片/宣传片）

**现有系统改造**：从 Stage 11 的【渲染参数】+【导演指令】中拆分，独立为 P0 字段，置于 prompt 最前端。

#### 新增2：【约束】constraint（P0）

**业务功能**：底层技术参数，不可协商。

**标准内容**：
```
Aspect ratio: 16:9, Resolution: 1920x1080, Format: MP4, Frame rate: 24fps
```

**生成方式**：系统硬编码注入，依据项目配置自动填充，不依赖LLM。

**现有系统改造**：从【渲染参数】中拆分技术参数部分，独立为硬编码字段。

#### 新增3：【基础】baseline（P0）

**业务功能**：画质锚定词，确立最低质量标准。

**三类基础词**：
- 分辨率锚定：`8K resolution, ultra high definition, 4K crisp detail`
- 风格质量：`cinematic quality, photorealistic, hyperrealistic`
- 细节增强：`highly detailed, intricate textures, fine details, sharp focus`

**生成方式**：系统硬编码注入，按视频类型差异化配置。

| 视频类型 | 推荐基础词组合 |
|---------|--------------|
| 教育类 | `8K resolution, crisp detail, clear visuals, highly detailed` |
| 剧情类 | `cinematic quality, photorealistic, film grain, dramatic lighting` |
| 广告类 | `ultra high definition, vibrant colors, glossy finish, premium quality` |

**现有系统改造**：从【负面约束】中拆分画质相关词汇，独立为前置字段。

#### 新增4：【构图】composition（P1）

**业务功能**：景别+主体位置+线条引导，控制画面信息密度。

**景别五级**：远景(ELS) → 全景(LS) → 中景(MS) → 近景(CU) → 特写(ECU)

**主体位置三种**：三分法构图 / 中心构图 / 对称构图

**生成方式**：VisualLanguageAgent 根据场景空间特征、角色数量、叙事重点生成。

**现有系统改造**：原有【运镜】包含景别信息，但不够独立和精细。新增独立字段，从运镜中拆分景别和构图逻辑。

#### 新增5：【色彩/色调】color_palette（P1）

**业务功能**：调色方案，与【导演指令】情绪基调保持一致。

**四维度描述**：
- 主色调：`dominant teal-cyan tone`
- 辅助色：`accented with warm amber highlights`
- 饱和度：`muted saturation at 60%`
- 对比度：`high contrast with deep shadows`

**常见模板**：冷暖对比 / 单色调 / 复古胶片 / 高饱和商业

**生成方式**：VisualLanguageAgent 根据 `contentTheme` + `mood` + 场景类型生成。

**现有系统改造**：从【风格】字段中拆分色彩部分，独立为 P1 字段。

#### 新增6：【景深】depth_of_field（P1）

**业务功能**：焦点控制，区分"监控录像"与"电影质感"的关键参数。

**三要素**：焦点位置 + 虚化程度 + 清晰范围

**标准描述**：
```
depth_of_field: "shallow depth of field, focus on the subject's face, background heavily blurred with creamy circular bokeh"
```

**生成方式**：VisualLanguageAgent 根据构图方案、叙事重点生成。单主体默认浅景深，多主体默认深景深。

**现有系统改造**：全新字段，需在 Stage 9 或新增 VisualLanguageAgent 中生成。

#### 新增7：【服装】costume（P2）【化妆】makeup（P3）【道具】props（P2）【节奏】pacing（P2）【转场】transition（P3）

这些字段按规范定义的标准格式生成，由专用 Agent 负责。

### 2.3 扩展字段改造（6个）

#### 扩展1：【场景】scene → 三维度描述法

**现有**：`开场介绍` / `核心症状讲解`（简单场景名）

**目标**：`interior of a modern hospital ward, clean white walls with medical equipment along the bedside, bright fluorescent ceiling lights, contemporary setting, daytime`

**三维度**：空间类型(Where) + 环境特征(What) + 时代背景(When)

**改造方式**：SceneDesignAgent 基于剧本内容生成完整描述，PromptFusionAgent 在融合时注入。

#### 扩展2：【灯光】lighting → 五要素框架

**现有**：`自然光，柔和明亮，均匀照明`（简单描述）

**目标**：`key light: soft diffused window light from camera left at 5600K, fill light: subtle LED panel at 4000K from camera right, low contrast ratio 2:1`

**五要素**：光源类型 + 色温 + 光质 + 光位 + 光比

**改造方式**： LightingDesignAgent（新增）或 VisualLanguageAgent 生成，质量检查强制要求五要素齐全。

#### 扩展3：【运镜】camera_movement → 七种方式+速度+时间

**现有**：`稳定推进，适度跟随`（模糊描述）

**目标**：`slow push in toward the protagonist's face, 0.5m/s constant speed, starting from medium shot distance and ending at close-up, duration 3 seconds`

**七种方式**：推(Push In) / 拉(Pull Out) / 摇(Pan) / 移(Track) / 跟(Follow) / 升降(Crane) / 环绕(Orbit)

**改造方式**：VisualLanguageAgent 替代现有 Stage 9，增加速度参数和时间分布。

#### 扩展4：【角色】character → 三维度描述法

**现有**：`陈卓`（过于简单）

**目标**：`a 35-year-old East Asian female, medium build, standing upright facing camera three-quarter view, calm and focused eyes, slight natural smile`

**三维度**：身份描述 + 姿态 + 表情

**改造方式**：Stage 4 角色系统升级，增加 `visualAnchors` 标准格式，PromptFusionAgent 生成时注入姿态和表情维度。

#### 扩展5：【动作】action → 三要素结构

**现有**：`左手平举至胸前模拟肌肉位置`（简单描述）

**目标**：`gesturing with right hand while speaking, fingers slightly spread, looking toward the listener`

**三要素**：主体动作 + 辅助动作 + 视线方向

**改造方式**：VisualLanguageAgent 生成，与【台词】字段进行时序配合（台词时段内避免遮挡嘴部动作）。

#### 扩展6：【时间轴】timeline → 分段式描述

**现有**：`00:00-00:08 / 时长:8s`（简单时间格式）

**目标**：
```
T00:00 - 中景，主角坐在桌前，专业环境；主角缓缓抬起头，目光投向镜头
T00:03 - 近景过渡，镜头缓慢推进至面部；主角眼神坚定，嘴角微微抿紧
T00:06 - 特写定格，主角眼部区域；眼睛眨动一次，瞳孔中反射出环境光
```

**改造方式**：系统计算时间 + LLM 生成画面内容和动作描述，分段数≥3。

## 三、链路架构改造：从 Stage 串联到 Phase 并行

### 3.1 现有架构问题

现有系统采用 **Stage 0-11 串联执行**，每个 Stage 必须等待前一个 Stage 完成：

```
Stage 1 → Stage 2 → ... → Stage 11 → toStandardPrompt → 输出
```

**问题**：
1. 总耗时 540-600 秒，调用方需设置 timeout ≥ 900s
2. 各 Stage 内部无法并行，LLM 调用串行等待
3. 部分 Stage 之间无数据依赖，但被迫串行

### 3.2 目标架构：Layer + Phase + Agent

```
┌─────────────────────────────────────────────────────────────┐
│ Layer 0: 需求确认（人工/已有）                              │
│ 输入: 用户原始需求 → 输出: 确认后的需求清单                    │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ Layer 1: 剧本引擎（ScriptEngine）                            │
│ 输入: 需求清单 → 输出: ScriptBlueprint（角色+台词+场景骨架） │
│ 对应现有: Stage 1 (PRD) + Stage 5 (剧本)                     │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ FormatAdapter: 场景→镜头转换                                 │
│ 输入: 6个场景 → 输出: shot[] 数组（含 scene, characters等）  │
│ 对应现有: Stage 6 (时长分配) + Stage 7 (故事板)               │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ Layer 2 Phase 1: 空间与角色基础（并行）                      │
│ ┌─────────────┐ ┌─────────────┐ ┌─────────────┐           │
│ │SceneDesignAgent│ │LightingDesignAgent│ │CostumeDesignAgent│ │
│ │ 输出:场景    │ │ 输出:灯光    │ │ 输出:服装    │           │
│ └─────────────┘ └─────────────┘ └─────────────┘           │
│ ┌─────────────┐ ┌─────────────┐                            │
│ │MakeupDesignAgent│ │PropsDesignAgent│                      │
│ │ 输出:化妆    │ │ 输出:道具    │                            │
│ └─────────────┘ └─────────────┘                            │
│ 注: 5个Agent并行执行，无数据依赖                             │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ Layer 2 Phase 2: 镜头语言与叙事节奏（并行）                │
│ ┌─────────────────────────┐ ┌─────────────────────────┐     │
│ │   VisualLanguageAgent   │ │     AudioDesignAgent    │     │
│ │ 输出:构图/色彩/景深/运镜 │ │ 输出:音频               │     │
│ │      /动作/情绪         │ │                         │     │
│ └─────────────────────────┘ └─────────────────────────┘     │
│ ┌─────────────────────────┐                                │
│ │   ContinuityReviewAgent  │                                │
│ │ 输出:连续性检查报告        │                                │
│ └─────────────────────────┘                                │
│ 注: VisualLanguageAgent内部6个字段串行，但Agent之间并行     │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ Layer 2 Phase 3: 字段融合与注入（PromptFusionAgent）       │
│ 步骤1: 收集Phase 1+2所有字段输出                              │
│ 步骤2: 注入硬编码字段（约束/基础/定妆照/角色一致性/负面/   │
│        明亮约束/角色约束）                                   │
│ 步骤3: LLM生成导演指令/时间轴/节奏/转场                      │
│ 步骤4: 按P0-P3优先级排序组装                                 │
│ 对应现有: Stage 11 + toStandardPrompt                         │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ DirectorSkillInjector（可选）: 导演技能增强                   │
│ 三套模板: 雨夜手持/史诗斯坦尼康/温情斯坦尼康                  │
│ 对应现有: Stage 8.4 (电影摄影技能注入)                       │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ FieldGuard: 字段校验                                          │
│ P0完整性检查(12项) + P1完整性检查(7项) + 内容专业性(19项)    │
│ 字符数检查 + 跨字段一致性检查                                 │
│ 对应现有: RenderPipelineGuard + RenderQAChecker              │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ 最终输出: render-tasks.json（25字段/shot，≤2500字符）        │
└─────────────────────────────────────────────────────────────┘
```

### 3.3 并行化收益测算

| 环节 | 现有串行耗时 | 目标并行耗时 | 节省 |
|------|-----------|-----------|------|
| Phase 1 (5个Agent) | 5 × 15s = 75s | max(15s) = 15s | -60s |
| Phase 2 (3个Agent) | 6 × 20s + 10s = 130s | max(20s, 10s) = 20s | -110s |
| Phase 3 (融合) | 120s | 120s | 0s |
| FieldGuard (校验) | 30s | 30s | 0s |
| **总计** | ~355s | ~185s | **-170s（缩短48%）** |

> 注：以上仅为Agent并行部分的测算，不含Layer 1剧本引擎时间。总耗时预计从540-600s降至300-350s。

## 四、LLM环节扩展与并行化设计

### 4.1 新增专用Agent清单

| Agent名称 | 负责字段 | 输入 | 输出 | 执行方式 |
|----------|---------|------|------|---------|
| SceneDesignAgent | 场景 | 剧本场景概要 | 三维度场景描述 | 并行 |
| LightingDesignAgent | 灯光 | 场景类型、时间设定、情绪基调 | 五要素灯光描述 | 并行 |
| CostumeDesignAgent | 服装 | 角色对象、时代背景、季节 | 分层服装描述 | 并行 |
| MakeupDesignAgent | 化妆 | 角色对象、场景类型、情绪基调 | 妆容+发型描述 | 并行 |
| PropsDesignAgent | 道具 | 场景类型、角色动作、主题 | 位置标注道具 | 并行 |
| VisualLanguageAgent | 构图/色彩/景深/运镜/动作/情绪 | 场景空间特征、角色数量、叙事重点 | 6个字段 | 并行（内部串行） |
| AudioDesignAgent | 音频 | 场景类型、情绪基调 | 三层音频描述 | 并行 |
| ContinuityReviewAgent | 连续性检查 | 所有已生成字段 | 连续性检查报告 | 并行 |
| PromptFusionAgent | 全部25字段融合 | Phase 1+2输出 + 硬编码字段 | 完整prompt | 串行（Phase 3） |
| DirectorSkillInjector | 导演技能增强 | 融合后的prompt | 增强后的prompt | 串行（可选） |
| FieldGuard | 质量校验 | 最终prompt | 通过/失败报告 | 串行 |

### 4.2 LLM提示词长度扩展

现有各Stage LLM提示词长度参考：

| Stage | 现有maxTokens | 目标maxTokens | 扩展理由 |
|------|-------------|-------------|---------|
| Stage 1 (PRD) | 4096 | 4096 | 不变，已足够 |
| Stage 5 (剧本) | 1536 | 2048 | 需生成更多字段（动作、服装等） |
| Stage 7 (故事板) | 2048 | 3072 | 需输出更详细的shot结构 |
| Stage 9 (运镜) | 1024 | 2048 | 需生成构图、色彩、景深等 |
| Stage 11 (渲染) | 4096 | 4096 | 不变，但prompt模板需扩展 |
| PromptFusionAgent | 无（新） | 4096 | 新Agent，需融合25字段 |
| SceneDesignAgent | 无（新） | 1024 | 新Agent，场景描述 |
| VisualLanguageAgent | 无（新） | 2048 | 新Agent，6个字段 |
| AudioDesignAgent | 无（新） | 1024 | 新Agent，音频描述 |

### 4.3 分段调用策略（PromptFusionAgent）

PromptFusionAgent 按三批生成，避免单次LLM调用负荷过大：

**第一批（空间相关字段）**：场景 + 灯光 + 构图 + 色彩 + 景深
- 输入：scene描述 + 情绪基调 + 场景类型
- 输出：5个字段的完整描述

**第二批（角色相关字段）**：角色 + 服装 + 化妆 + 道具 + 动作
- 输入：character对象 + 场景时代背景 + 台词内容
- 输出：5个字段的完整描述

**第三批（叙事节奏字段）**：导演指令 + 时间轴 + 节奏 + 转场 + 音频
- 输入：filmType + creativityIndex + contentTheme + 前两批输出
- 输出：5个字段的完整描述

**硬编码注入（最后组装）**：约束 + 基础 + 定妆照 + 角色一致性 + 负面约束 + 明亮约束 + 角色约束

## 五、字符数管理与超限处理

### 5.1 2500字符上限的制定依据

选择 **2500字符**（而非3000）的四项考量：
1. 25字段 × 平均100字符 = 2500，理论测算值与实际上限完全匹配
2. 保留适度余量，允许个别字段突破平均值
3. 3000字符可能触及部分底层API的输入长度限制，增加集成风险
4. 2500作为阶段性验证值，可在实际生产数据中检验充足性

### 5.2 各字段字符预算分配

| 优先级 | 字段 | 预算字符 | 可压缩性 | 超限处理顺序 |
|-------|------|---------|---------|------------|
| P0 | 导演指令 | 50-80 | 否 | 保护 |
| P0 | 约束 | 100-150 | 否 | 保护 |
| P0 | 基础 | 80-100 | 否 | 保护 |
| P0 | 场景 | 150-200 | 是 | Step 5 |
| P0 | 灯光 | 100-150 | 是 | Step 4 |
| P0 | 运镜 | 80-120 | 是 | Step 4 |
| P0 | 角色 | 50-80 | 是 | Step 5 |
| P0 | 动作 | 100-150 | 是 | Step 5 |
| P0 | 台词 | 按实际 | 否 | 保护 |
| P0 | 负面约束 | 200-300 | 否 | 保护 |
| P0 | 定妆照 | 系统注入 | 否 | 保护 |
| P0 | 角色一致性 | 50-80 | 否 | 保护 |
| P1 | 构图 | 80-120 | 是 | Step 4 |

| P1 | 明亮约束 | 50-80 | 否 | 保护 |
| P1 | 角色约束 | 50-80 | 否 | 保护 |
| P2 | 服装 | 60-100 | **优先裁剪** | Step 3 |

**P0合计**：约960-1490字符（不含定妆照系统注入）
**P1合计**：约470-670字符
**P2合计**：约220-380字符
**P3合计**：约70-110字符
**总计**：约1720-2650字符

### 5.3 六步截断策略

```
Step 1: 冗余检测与去重（释放50-200字符）
  → 检测字段间重复描述，删除重叠部分
  → 保留优先级高的字段版本

Step 2: P3字段裁剪（释放70-110字符）
  → 化妆缩短描述或完全移除
  → 转场缩短描述或完全移除

Step 3: P2字段压缩（释放200-380字符）
  → 服装、道具、节奏、音频逐字段缩短
  → 从完整描述退化为关键词级别

Step 4: P1字段压缩（释放80-200字符）
  → 时间轴减少分段数
  → 情绪退化为单关键词
  → 构图、色彩、景深退化为关键词
  → 保留灯光、运镜、明亮约束、角色约束完整性

Step 5: P0字段压缩（释放100-300字符）
  → 场景保留核心空间信息
  → 动作保留主干动词链
  → 角色保留身份特征
  → 台词/负面约束/角色一致性始终受保护

Step 6: 超限报警（终止自动处理）
  → 向用户输出超限提示
  → 人工决策：接受更高压缩率或拆分镜头
```

## 六、质量检查升级：FieldGuard

### 6.1 现有检查 vs 目标检查

| 维度 | 现有系统 | 目标系统 | 升级点 |
|------|---------|---------|--------|
| 检查项数 | ~10项 | 25项 | +15项 |
| 检查分类 | 2类（P0/P1） | 4类（P0/P1/P2/P3） | 增加P2/P3检查 |
| 内容专业性 | 无 | 19项正则规则 | 新增 |
| 跨字段一致性 | 无 | 有 | 新增 |
| 字符数管理 | 简单长度检查 | 六步截断策略 | 升级 |

### 6.2 FieldGuard 检查清单（25项）

**P0致命级检查（12项）**：
- [ ] 导演指令：含风格定位+写实要求+情绪基调
- [ ] 约束：含画幅+分辨率+格式+帧率
- [ ] 基础：含有效画质锚定词
- [ ] 场景：含空间类型+环境特征+时代背景
- [ ] 灯光：含主光+色温+光质
- [ ] 运镜：含运动方式+速度+时间分布
- [ ] 角色：含至少一个有效角色描述
- [ ] 动作：与场景和台词语义一致
- [ ] 台词：有配音需求时非空
- [ ] 负面约束：含"no text"+"no watermark"
- [ ] 定妆照：路径正确且文件可访问
- [ ] 角色一致性：含跨镜特征锚定词

**P1核心级检查（7项）**：
- [ ] 构图：含景别等级+主体位置
- [ ] 色彩：含主色调+饱和度
- [ ] 景深：含焦点位置+虚化程度
- [ ] 时间轴：分段数≥3，每段含时间戳和动作
- [ ] 情绪：与导演指令情绪基调一致
- [ ] 明亮约束：含亮度+可见性+面部明亮
- [ ] 角色约束：含单角色限制+禁止分身

**P2增强级检查（4项）**：
- [ ] 服装：含外套/内搭/下装/鞋履中至少3项
- [ ] 道具：位置标注正确（/held /table /bg）
- [ ] 节奏：含五段节奏结构
- [ ] 音频：含环境音+音乐风格+音量层级

**P3可选级检查（2项）**：
- [ ] 化妆：含面部妆容+发型+整体造型
- [ ] 转场：含切镜/淡入/淡出/叠化中至少一种

**通用检查（5项）**：
- [ ] 提示词总长度：≤2500字符
- [ ] 跨字段一致性：导演指令与情绪/色彩一致
- [ ] 冗余检测：无字段间重复描述
- [ ] 英文关键词优先：技术术语使用英文
- [ ] 格式规范：逗号分隔关键词，避免长句从句

### 6.3 与现有检查环节的整合

现有检查环节：
- `RenderPipelineGuard`（Stage 11前）
- `RenderQAChecker`（Stage 11后）

目标整合方案：
- `RenderPipelineGuard` → 升级为 `FieldGuard` P0+P1检查模块
- `RenderQAChecker` → 升级为 `FieldGuard` P2+P3+通用检查模块
- 新增 `CrossFieldConsistencyChecker`（跨字段一致性检查）
- 新增 `RedundancyDetector`（冗余检测与去重）
