# 暴风战斧AI视频生成系统 — 最终字段规范 v1.0

> 文档定位：明确系统最终输出给 Seedance 渲染引擎的 prompt 字段全貌，以及这些字段从哪个环节来、怎么生成、起什么作用。

---

## 一、最终输出字段总览

系统最终输出的是 **每个镜头（Shot）的渲染提示词（Prompt String）**，由 `toStandardPrompt()` 方法组装。一个完整的最终 prompt 由以下 **中文标记字段** 构成，以 ` | ` 分隔：

| 序号 | 字段标记 | 业务含义 | 渲染作用 |
|:---:|---------|---------|---------|
| 1 | `【视觉】` | 视觉风格前置标识 | 告知 Seedance 进入视觉描述模式 |
| 2 | `【角色】` | 角色外观核心描述 | 锁定角色形象，绑定定妆照 |
| 3 | `【场景】` | 场景名称 | 确定镜头发生的空间背景 |
| 4 | `【空间】` | 五维空间增强描述 | **关键**：决定画面环境、纵深、方位、氛围、时间 |
| 5 | `【动作】` | 角色动作描述 | 驱动角色在镜头中的行为 |
| 6 | `【台词】` | 旁白/台词内容 | 驱动嘴部动作与表情 |
| 7 | `【全局时间定位】` | 镜头时间轴 | 确保音画同步、转场衔接 |
| 8 | `【运镜】` | 摄像机运动描述 | 决定镜头运动方式 |
| 9 | `【情绪】` | 情绪阶段 | 影响角色表情与氛围 |
| 10 | `【音频】` | 声音设计 | 环境音、音乐、人声处理 |
| 11 | `【风格】` | 色彩/美学风格 | 统一画面视觉调性 |
| 12 | `【负面约束】` | 禁止内容 | 排除不希望出现的元素 |
| 13 | `【明亮约束】` | 亮度/光照约束 | 确保画面明亮清晰 |
| 14 | `【角色约束】` | 角色出现限制 | 防止多角色/重复角色 |
| 15 | `【绑定定妆照】` | 参考图引用 | **关键**：角色一致性保障 |
| 16 | `【灯光】` | 灯光方案 | 补充光照细节 |
| 17 | `【渲染参数】` | 画质/技术参数 | 指定分辨率、帧率、风格 |
| 18 | `【导演指令】` | 导演风格指令 | 整体创作意图 |

> **核心原则**：最终 prompt 是一个**单层扁平字符串**，所有字段通过 ` | ` 拼接，供 Seedance 直接消费。

## 二、业务视角规范

### 2.1 字段分级（按重要性）

| 级别 | 字段 | 说明 |
|-----|------|------|
| **P0-致命** | `【角色】` `【场景】` `【动作】` `【绑定定妆照】` | 缺失则视频无法生成或角色错误 |
| **P1-核心** | `【空间】` `【台词】` `【运镜】` `【全局时间定位】` | 缺失则内容质量大幅下降 |
| **P2-增强** | `【情绪】` `【灯光】` `【音频】` `【风格】` | 提升质感，缺失仍可生成 |
| **P3-约束** | `【负面约束】` `【明亮约束】` `【角色约束】` | 防御性字段，过滤不良输出 |
| **P4-元数据** | `【渲染参数】` `【导演指令】` | 技术参数，通常由配置决定 |

### 2.2 字段内容质量标准

#### `【角色】`
- **必须包含**：角色姓名、服装细节、外观锚点
- **质量标准**：≥50 字符，具体到服装款式、颜色、配饰
- **示例**：`陈卓身穿标准藏蓝色警用制服，佩戴警帽，左胸佩戴警徽和警号，两肩佩戴肩章，制服为平驳领、单排四粒扣西装款式`
- **反面教材**：`陈卓`（太短，无法锁定形象）

#### `【场景】`
- **必须包含**：场景名称（中文）
- **质量标准**：场景名应具体、有区分度，避免通用模板
- **示例**：`开场介绍` `核心症状讲解` `实验室检查与尿液变化`
- **反面教材**：`golden hour, clear sky, atmospheric haze`（英文模板，已列入黑名单拦截）

#### `【空间】`
- **必须包含**：空间、纵深、方位、氛围、时间（五维）
- **质量标准**：≥80 字符，每个维度独立成句
- **示例**：
  ```
  专业医疗环境，健康科普宣教室，墙面布置运动医学知识展板 | 
  【纵深】中景到近景过渡，前景有医疗设备 | 
  【方位】正面微仰视角，人物占据画面视觉中心 | 
  【氛围】专业、权威、可信赖 | 
  【时间】明亮均匀的室内照明，色温4500K-5500K
  ```

#### `【动作】`
- **必须包含**：角色具体动作、手势、姿态
- **质量标准**：动词明确，有画面感
- **示例**：`左手平举至胸前模拟肌肉位置，右手同步做按压手势，随后双手合拢下移至腹部`

#### `【台词】`
- **必须包含**：旁白文本（如有说话）
- **质量标准**：与时长匹配，语速合理
- **参考**：1秒 ≈ 3-4 个中文字

#### `【运镜】`
- **必须包含**：景别 + 运动方式
- **质量标准**：避免所有镜头使用相同运镜
- **差异化要求**：相邻镜头景别或运动方式至少改变一项

#### `【绑定定妆照】`
- **必须包含**：`@imageN` 格式引用
- **质量标准**：每个有角色的镜头必须引用
- **格式**：`【绑定定妆照】@image1 chen-zhuo近景,核心特征,超写实`

## 三、字段生产链路

### 3.1 全流程 Stage 地图

```
用户输入
  ↓
[Stage 1] PRD中央校准文档 —— 生成 title, topic, characters, scenes(骨架)
  ↓
[Stage 2] 需求对齐闸机 —— 校验 PRD 完整性
  ↓
[Stage 3] Schema校验 —— 数据结构验证
  ↓
[Stage 4] 角色系统 —— 构建 character-card.json, portraits, visualAnchors
  ↓
[Stage 5] 剧本生成 —— 生成 narration, dialogue, action, scene(初版)
  ↓
[Stage 5.5] FPV镜头决策 —— 决定镜头视角策略
  ↓
[Stage 6] 时长分配 —— 计算 duration, 校验总时长
  ↓
[Stage 7] 故事板生成 —— 生成 shots 数组，每个 shot 含 scene, characters, action, dialogue
  ↓
[Stage 7.2] 主角主动性注入 —— 强化主角动作
  ↓
[Stage 7.4] 时长-字数校准 —— 调整 narration 长度匹配 duration
  ↓
[Stage 7.5] 片头自动生成 —— 生成 S00 片头 shot
  ↓
[Stage 8] 故事板校验 —— 校验 shots 完整性
  ↓
[Stage 8.4] 电影摄影技能注入 —— 注入 lighting, camera 专业术语
  ↓
[Stage 8.5] 五要素检查 —— 质量闸机
  ↓
[Stage 9] 运镜系统 —— 生成 cameraMovement (shotSize, movement, lens)
  ↓
[Stage 10] 连续性检查 —— 校验镜头间连贯性
  ↓
[Stage 10.5] 渲染前置输入检查 —— 确认 Stage 11 输入完整性
  ↓
[Stage 11] 渲染核心 —— LLM 生成 prompt 主体内容
  ↓
[Stage 11.5] 空间增强 Agent —— 生成/增强【空间】五维描述
  ↓
[Stage 11.6] Prompt质量闸门 —— 校验 prompt 质量
  ↓
toStandardPrompt() —— 组装最终 prompt 字符串
  ↓
Prompt Stability Guard —— 保护关键字段、稳定裁剪
  ↓
[输出] render-tasks.json —— 供 Seedance 渲染消费
```

### 3.2 关键字段的生成来源（逐字段）

| 字段 | 生成 Stage | 生成方式 | 关键依赖 |
|------|-----------|---------|---------|
| `【角色】` | Stage 11 (LLM) | LLM 根据 character-card.json 的 `visualAnchors` + `baseIdentity` 生成描述 | Stage 4 角色档案 |
| `【场景】` | Stage 5/7 | 剧本生成时确定场景名，Stage 7 故事板细化 | Stage 1 PRD 场景骨架 |
| `【空间】` | Stage 11.5 (空间增强) | `_extractSceneDescription()` 生成五维空间描述 | Stage 7 shot.scene |
| `【动作】` | Stage 5 (剧本) | LLM 根据 narration 生成匹配动作 | Stage 5 narration |
| `【台词】` | Stage 5 (剧本) | LLM 生成旁白文本 | Stage 1 topic/keyPoints |
| `【全局时间定位】` | Stage 11 | 计算 `_globalStartTime` + `_globalEndTime` | Stage 6 时长分配 |
| `【运镜】` | Stage 9 | cameraMovement 系统生成 | Stage 8.4 技能注入参数 |
| `【情绪】` | Stage 5/7 | emotionPhase 字段 | 叙事弧线设计 |
| `【音频】` | Stage 11 (LLM) | LLM 根据场景生成音频描述 | — |
| `【风格】` | Stage 8.4 | 电影摄影技能注入 | creativityIndex |
| `【负面约束】` | Stage 11 (硬编码) | 系统默认负面词 + 项目定制 | — |
| `【明亮约束】` | Stage 11 (硬编码) | 系统默认亮度要求 | filmType |
| `【角色约束】` | Stage 11 (硬编码) | 禁止重复角色提示 | characters 列表 |
| `【绑定定妆照】` | Stage 11 | `referenceImages` 数组 → `@imageN` 引用 | Stage 4 portraits |
| `【灯光】` | Stage 8.4/11 | lighting 系统生成 | Stage 8.4 技能参数 |
| `【渲染参数】` | Stage 11 (硬编码) | 质量等级 + 画幅 + 帧率 | config/seedance.json |
| `【导演指令】` | Stage 11 (LLM) | LLM 根据整体风格生成 | filmType + creativityIndex |

## 四、深度链路解析

### 4.1 Stage 11 渲染核心（最关键环节）

Stage 11 是整个系统的**最终内容生成器**。它接收上游所有 Stage 的输出，调用 LLM 为每个 shot 生成 prompt 主体。

**输入**：
- `storyboard.shots`：来自 Stage 7，含 scene, characters, action, dialogue, cameraMovement, lighting
- `stages.characters`：来自 Stage 4，含角色档案
- `mode`：运行模式（preproduction / production）

**处理流程**：
1. 调用 `STAGE_11_RENDER` LLM Prompt 模板
2. LLM 为每个 shot 生成包含【角色】【场景】【动作】【台词】等字段的 prompt
3. 调用 `toStandardPrompt()` 进行标准化组装
4. 调用 `_extractSceneDescription()` 增强【空间】字段（v6.6.6 起默认启用）
5. 注入【绑定定妆照】引用
6. 注入【全局时间定位】
7. 注入硬编码约束字段（负面约束、明亮约束、角色约束）

**输出**：
- 每个 shot 的 `prompt` 字符串（~1000-1500 字符）
- `render-tasks.json`：供 Seedance 调用

### 4.2 `_extractSceneDescription()` 空间增强（v6.6.6）

这是 **Stage 11.5** 的核心方法，负责将简单的场景名扩展为五维空间描述。

**功能**：
- 将 `shot.scene`（如 `"开场介绍"`）扩展为完整的空间描述
- 五维：空间、纵深、方位、氛围、时间
- 每个 shot 的空间描述必须**差异化**，相邻 shot 不得重复

**生成方式**：
- 基于 LLM，输入 shot 的 scene, action, dialogue
- 输出格式化的五维空间描述

**质量标准**：
- 中文描述
- ≥80 字符
- 五维齐全
- 镜头间不重复

### 4.3 `toStandardPrompt()` 组装逻辑

```javascript
function toStandardPrompt(shot, prompt) {
  // 1. 标签标准化（旧标签 → 新标签）
  // 2. 提取关键块（保护已有内容）
  // 3. 补缺口（缺失字段自动补充）
  // 4. 场景增强（调用 _extractSceneDescription）
  // 5. 拼接所有字段为单层字符串
  // 6. 稳定裁剪（优先保关键块，max 1500 字符）
  // 7. 二次恢复（防止误删）
}
```

**关键规则**：
- **只补不洗**：保留 LLM 生成的原始内容，不重新生成
- **优先保关键块**：裁剪时优先保留【角色】【场景】【动作】【台词】【绑定定妆照】
- **中文标签统一**：v6.6.3 起全部使用中文标记

### 4.4 Prompt Stability Guard（防御层）

在 `toStandardPrompt()` 之后执行，确保 prompt 结构稳定。

**功能**：
1. `提取关键块()`：从 prompt 中提取所有标记字段
2. `关键字段存在()`：检查关键字段是否齐全
3. `稳定裁剪()`：超长时优先保留关键块
4. `恢复关键块()`：裁剪后恢复被误删的关键字段
5. `最小补洞()`：最后兜底，确保【动作】【台词】【时间轴】存在

## 五、当前系统问题诊断

### 5.1 已发现的质量问题

| 问题 | 现象 | 根因 | 修复状态 |
|------|------|------|---------|
| 场景模板化 | 多个镜头场景描述相同 | `_extractSceneDescription` 未启用或生成雷同 | v6.6.6 已修复（强制五维差异化） |
| 运镜重复 | 所有镜头使用相同运镜 | `_buildDynamicLayer` 与 `toStandardPrompt` 双重注入 | v6.6.6 已修复（去重） |
| 角色一致性失败 | 渲染视频中角色错误 | `portraits` 键名不匹配 + `charCoreDesc` 硬编码 | v6.6.6 已修复 |
| ACTION 字段缺失 | prompt 中无动作描述 | Stage 5 未生成或 Stage 11 未传递 | v6.5.65-P8 已修复 |
| 场景英文模板 | 出现 `golden hour` 等英文 | LLM 生成英文场景，未拦截 | v6.6.6 已修复（黑名单拦截） |
| 时长计算异常 | 负时长或时间轴错误 | `_globalStartTime` 计算逻辑问题 | v6.6.6 已修复 |

### 5.2 待验证项

- [ ] `_extractSceneDescription` 默认启用后，是否显著提升空间描述质量
- [ ] Stage 11 LLM Prompt 模板是否需要升级以生成更高质量内容
- [ ] 检查环节（RenderPipelineGuard + RenderQAChecker）是否需要增加更多规则

## 六、质量标准 checklist（每条 prompt 输出前必检）

```
□ 【角色】≥50 字符，含服装细节
□ 【场景】中文，非英文模板，非通用词
□ 【空间】五维齐全，≥80 字符，与相邻镜头不重复
□ 【动作】动词明确，有画面感
□ 【台词】与时长匹配（1秒≈3-4字）
□ 【运镜】景别或运动方式与相邻镜头不同
□ 【全局时间定位】格式正确 00:00-00:00
□ 【绑定定妆照】@imageN 格式，每个角色镜头都有
□ 【负面约束】包含禁用词列表
□ 总长度 ≤1500 字符
□ 全中文标记，无 PromptTier-v2.0 旧标签残留
```
